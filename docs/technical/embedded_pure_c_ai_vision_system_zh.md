# 面向嵌入式与边缘设备的纯 C 语言 AI 视觉系统

> 目标：在不依赖闭源自动转换链路的前提下，基于本仓库已有方案（高反光工件视觉分拣）构建一套**可落地、可审计、可量产**的纯 C 嵌入式 AI 视觉技术体系。

---

## 1. 技术定位与边界

本方案借鉴业界在“模型压缩、自动代码生成、端侧推理优化”方面的工程经验，但坚持以下原则：

1. **不复刻特定工具实现细节**：仅吸收公开可验证的通用思想（量化、算子融合、内存复用、流水线调度）。
2. **全链路自研与可解释**：训练在 Python；部署端推理、图像预处理、后处理、调度框架均为纯 C。
3. **专利风险前置治理**：采用“需求-设计-实现-验证”四层文档化留痕，保留独立设计证据。
4. **工业优先**：面向 Cortex-M85 / Helium、RZ/V 系列、低功耗 NPU/MCU 的实时约束（低延时、低内存、确定性）。

## 3. 纯 C 推理运行时设计

### 3.1 数据结构

- `tensor_t`：`shape + stride + qparam + data_ptr`
- `op_node_t`：`op_type + input_idx + output_idx + kernel_param`
- `mem_block_t`：静态内存池块描述（生命周期分析后复用）
- `runtime_ctx_t`：执行图、工作区、性能计数器、错误码

### 3.2 执行模型

1. 启动时加载模型描述（自定义二进制或 C 数组）。
2. 依据拓扑顺序执行算子节点。
3. 每层执行后立即回收过期中间张量。
4. 全流程禁用动态 malloc（初始化后零碎片运行）。

### 3.3 量化策略

- **首选 INT8 对称量化**（权重 per-channel，激活 per-tensor）。
- 输出关键路径（边缘概率图）支持 INT16 累加防止精度塌陷。
- 校准集覆盖高反光场景：强高光、过曝、金属拉丝纹理。

## 4. 关键算法在 C 侧的实现映射

### 4.1 反光抑制前处理

- 3 帧曝光融合（短/中/长）
- 高光掩膜检测（阈值+局部对比）
- 引导式修复（邻域纹理一致性）

实现建议：
- 行缓存 + DMA 双缓冲；
- 使用整型近似替代高开销浮点；
- 对 3x3 / 5x5 核使用 Helium 向量化。

### 4.2 AGEANet-Lite 推理

- 深度可分离卷积 + 跳连解码结构
- CBAM 可裁剪为轻量通道注意力（部署开关）
- BN 融合到 Conv 权重与偏置，减少运行算子数量

### 4.3 亚像素定位

- 分割掩膜 -> 轮廓提取 -> Sobel 梯度
- Zernike 矩局部拟合获得亚像素边缘点
- RANSAC/最小二乘输出抓取中心与角度

## 6. 与现有仓库的集成落地路径

### 阶段 A：模型与数据冻结

1. 使用 `train.py` 训练 AGEANet-Lite。
2. 使用 `ra8p1_tflm_adapter.py` 导出并做离线校准。
3. 固化标准验证集（含高反光极端样本）。

### 阶段 B：纯 C Runtime 骨架上线

1. 在 `ra8p1_main_app.c` 中接入统一 runtime API。
2. 先打通 `Conv + DWConv + ReLU + Resize + Sigmoid` 最小闭环。
3. 与 Python 基线比对每层误差（余弦相似度 / MAE）。

### 阶段 C：性能与可靠性

1. 对 `ra8p1_helium_processing.c` 增加热点算子 SIMD 优化。
2. 建立周期级 profiling（每帧耗时、峰值内存、cache miss）。
3. 执行 72h 稳定性老化与光照扰动回归。

## 7. 专利规避与“新技术”构建方法（工程实践版）

> 说明：以下为工程流程建议，不构成法律意见。

### 7.1 Clean-room 研发机制

- 团队 A：只阅读公开论文/标准/官方文档，产出需求规格。
- 团队 B：不接触竞品实现，按规格独立编码。
- 双方均保留时间戳文档、评审记录、测试记录。

### 7.2 避免高风险动作

- 不反编译、不拷贝工具输出代码模板。
- 不使用与竞品高度相似的私有 IR/元数据格式。
- 不沿用竞争工具特有算子命名与序列化布局。

### 7.3 强化自有创新点（建议立项）

1. **高反光鲁棒校准集自动生成器**（结合偏振先验与曝光扰动）。
2. **边缘一致性驱动量化校准**（以边缘稳定性而非仅 Top-1 误差为目标）。
3. **分拣任务导向后处理图**（抓取可达性约束直接入图优化）。
4. **“可验证运行时”机制**（每层哈希与可追溯日志用于工业审计）。

## 8. 最小可用版本（MVP）指标

- 输入分辨率：`256x256` 灰度/伪彩
- MCU 目标：Cortex-M85 @ 400MHz
- 时延目标：`<= 80 ms/frame`（含前后处理）
- SRAM 峰值：`<= 2.5 MB`
- 精度目标：
  - IoU `>= 0.90`（验证集）
  - 边缘平均偏差 `<= 0.2 px`
  - 抓取角度误差 `<= 1.0°`

## 9. 建议的实施清单（30/60/90 天）

- **30 天**：完成 runtime 骨架、2~3 个关键算子、端到端单帧跑通。
- **60 天**：完成完整算子覆盖、Helium 优化、批量数据回归。
- **90 天**：完成产线联调、异常追溯系统、版本冻结与量产文档。

## 10. 结语

这条路线的核心不是“复制某个工具”，而是构建一套**面向高反光工业分拣场景的自主纯 C 视觉技术栈**：

- 在算法上，继承本仓库 AGEANet + HDR + 亚像素定位的有效性；
- 在工程上，形成可裁剪、可审计、可长期维护的嵌入式 runtime；
- 在知识产权上，通过 clean-room 与文档化创新，沉淀自有技术资产。
