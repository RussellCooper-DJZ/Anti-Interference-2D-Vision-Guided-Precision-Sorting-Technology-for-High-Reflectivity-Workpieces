# 迭代价值门控指南（Iteration Gate Guide）

> **目标**：防止未来迭代偏离项目核心价值主线，确保每一次迭代都产生可验证、可沉淀、可复用的技术资产。

---

## 一、核心价值六问（The Six Gate Questions）

任何新迭代在 **Plan 阶段** 必须通过以下六个问题中的**至少一个**：

```
┌─────────────────────────────────────────────────────────────────┐
│  1. 是否直接改进了边缘识别精度？                                  │
│     → 新注意力、新卷积、新损失、新架构                            │
├─────────────────────────────────────────────────────────────────┤
│  2. 是否增强了对高反光的鲁棒性？                                  │
│     → HDR改进、光度立体、高光修复、反光抑制                      │
├─────────────────────────────────────────────────────────────────┤
│  3. 是否提升了定位/测量精度？                                    │
│     → 亚像素算法、RANSAC、标定优化、坐标变换                      │
├─────────────────────────────────────────────────────────────────┤
│  4. 是否加速了推理或降低了部署成本？                              │
│     → 量化、剪枝、蒸馏、SIMD、多后端推理                          │
├─────────────────────────────────────────────────────────────────┤
│  5. 是否解决了数据稀缺问题？                                     │
│     → 合成生成、域适应、数据增强、半监督学习                      │
├─────────────────────────────────────────────────────────────────┤
│  6. 是否提升了机器人抓取成功率？                                  │
│     → 路径规划、碰撞检测、手眼标定、抓取策略                      │
└─────────────────────────────────────────────────────────────────┘
```

**判定规则**：
- ✅ **通过**：至少满足 1 条 → 允许进入 Work 阶段
- ⚠️ **有条件通过**：满足 0 条，但与核心价值间接相关 → 需额外论证，限制代码量 < 200 行
- ❌ **拒绝**：满足 0 条，且与核心价值无关 → 直接拒绝，不进入 Work 阶段

---

## 二、快速决策流程

```
新迭代想法
    │
    ▼
┌─────────────────────┐
│ 核心价值六问         │
│ (5 分钟自评)         │
└─────────────────────┘
    │
    ├─ 通过 ──→ 继续 Plan → Work → Review → Compound
    │
    ├─ 有条件通过 ──→ 需写 200 字论证 → 限制代码量 < 200 行 → 快速验证
    │
    └─ 拒绝 ──→ 记录到 "待探索想法池" → 不启动迭代
```

## 四、预提交检查清单（Pre-Work Checklist）

在开始编写 Work 代码前，必须确认：

```markdown
- [ ] 本迭代通过了核心价值六问中的至少一条
- [ ] 本迭代的预期产出可以量化（如 IoU +3%、延迟 -50% 等）
- [ ] 本迭代不依赖尚未实现的其他迭代
- [ ] 本迭代的代码量预估在合理范围内（算法改进 < 500 行，工具脚本 < 200 行）
- [ ] 如果涉及知名算法，已确认论文引用准确
- [ ] 如果修改了主代码库接口，已评估对其他模块的影响
```

---

## 五、迭代后审查清单（Post-Work Checklist）

Work 完成后、Review 前：

```markdown
- [ ] 代码通过语法检查 (`python -m py_compile`)
- [ ] 前向传播测试通过（如果是 nn.Module）
- [ ] 如果是算法改进，已对照论文/参考实现验证公式正确性
- [ ] 如果是数据增强，已验证 mask-图像一致性
- [ ] docstring 包含迭代编号、算法名称、核心改进点
- [ ] 代码风格符合 black/flake8 规范
```

---

## 六、禁止清单（Anti-Patterns）

以下类型的迭代 **原则上不允许**：

1. **通用 SaaS 平台功能**：多租户、API 网关、服务网格、计费系统
2. **混沌工程/可观测性**：除非直接与模型推理稳定性相关
3. **纯文档迭代**：文档改进应作为算法迭代的附带产出，而非独立迭代
4. **重复造轮子**：如果已有开源工具（如 MLflow、DVC、Optuna），不应自建替代品
5. **过早优化**：在核心算法未达基线前，不应投入推理优化
